# equipment-service-manual-troubleshooting-assistant

Enter a fault code or symptom and get step-by-step troubleshooting with page citations from equipment service manuals. Runs on an ordinary laptop CPU with a small local LLM (Ollama) by default; any OpenAI-compatible hosted API is optional.

> Status: scaffold. Ingestion, retrieval, the agent and the UI are tracked in the roadmap below.

## Quick start

```bash
pip install -e ".[dev]"
cp .env.example .env
manual-assistant status
pytest
```

With Docker (starts Ollama and the app):

```bash
docker compose up --build
docker compose exec ollama ollama pull qwen2.5:3b-instruct
```

## Ingest a manual

Drop service-manual PDFs into `data/manuals/` (a fictional sample lives in `data/samples/`) and run:

```bash
manual-assistant ingest --manuals-dir data/samples
```

This writes `data/index/chunks.jsonl`: one chunk per PDF page with the manual name, page number, detected model, system/section and any fault-code table rows (`E101  Hydraulic oil temperature too high`). The sample manual is regenerated with `python scripts/make_sample_manual.py` (needs `reportlab`).

## Search

```bash
manual-assistant search "E101" --index data/index/chunks.jsonl
manual-assistant search "engine overheating coolant"
```

Retrieval fuses BM25 keyword ranking (fault codes such as `E101` stay whole tokens) with dense embeddings via reciprocal rank fusion. Each hit is a page, printed as `[manual.pdf, p. 3]`. The default embedder is an offline character n-gram hashing embedder (no model download, works in any language). For semantic multilingual embeddings install `pip install -e ".[embeddings]"` and pass `SentenceTransformerEmbedder()` to `HybridRetriever`.

## Ask (fault-code tool + agent)

```bash
manual-assistant lookup E101                      # exact table lookup, with page citation
manual-assistant ask "What does E101 mean?"       # LLM answer from tool result + retrieved pages
manual-assistant ask "E101" --no-llm              # evidence only, fully offline
```

The agent extracts fault codes from the question (`E101`, `F-2040`, `SPN 100 FMI 3`), looks them up exactly in the tables captured at ingestion, retrieves the best pages with hybrid search and asks the LLM to answer only from that evidence, citing `[manual, p. N]`. Citations the model invents are dropped. If the LLM endpoint is unreachable the agent falls back to an extractive, still-cited answer.

## Multilingual questions

Ask in English, German, French, Spanish, Italian, Portuguese or Dutch; the answer comes back in the same language.

```bash
manual-assistant ask "Das Hydrauliköl wird zu heiß. Was soll ich prüfen?" --no-llm
manual-assistant ask "What does H101 mean?" --lang fr      # force the answer language
```

The question language is detected with a small stop-word detector (override with `--lang` or the UI dropdown) and the LLM is told to answer in it, translating the evidence while keeping fault codes and `[manual, p. N]` citations unchanged. Manuals are usually English, so for German, French and Spanish questions a built-in glossary of common service terms (hydraulic oil, pressure, steering, bucket, ...) is appended to the retrieval query in English, which lets BM25 match English pages offline. Fault-code lookup is language independent. For broader cross-lingual recall install the `embeddings` extra, which uses `intfloat/multilingual-e5-small`. The offline (no-LLM) answer uses localized labels. The glossary is intentionally small; extend `_GLOSSARY` in `src/manual_assistant/i18n.py` for more terms or languages.

## Web UI

```bash
pip install -e ".[ui]"
manual-assistant ui --index data/index/chunks.jsonl     # http://127.0.0.1:7860
```

Upload one or more service-manual PDFs (re-uploading a manual replaces its pages), type a fault code or symptom and read the answer. Every cited source is listed as a clickable choice; selecting one shows the full manual page text with its model and system. Add `--no-llm` for evidence-only answers. With `docker compose up --build` the UI is not started by default; run `docker compose run --service-ports assistant ui --host 0.0.0.0`.

## Evaluation

```bash
manual-assistant eval            # offline: hybrid retrieval + extractive answers
manual-assistant eval --llm      # same questions through the configured LLM
```

`data/eval/` holds two **fictional** manuals (a wheel loader and a crawler dozer, 21 fault codes) and 63 labelled questions, generated by `scripts/make_eval_set.py`. They are invented, not real manufacturer documents: public real manuals were not reachable when this set was built, so scores here say how well retrieval and citation work on clean, text-based PDFs, not on scanned or messy real-world manuals. Each question lists the accepted manual pages and a keyword the answer evidence must contain.

Results with the default offline setup (character n-gram hashing embeddings, no LLM):

| question kind | n | top-1 citation | top-3 citation | agent citation | answer support |
|---|---|---|---|---|---|
| code (`What does H101 mean?`) | 21 | 95% | 100% | 100% | 100% |
| code_steps (`How do I fix fault H101 ...?`) | 21 | 71% | 100% | 100% | 38% |
| symptom (free-text description) | 21 | 38% | 57% | 57% | 57% |
| overall | 63 | 68% | 86% | 86% | 65% |

"Answer support" means a keyword appears in the answer or in a cited page; the extractive fallback prints only each page's first line, so it is low for step questions. Symptom questions are the weak spot of the n-gram embedder; the `embeddings` extra (multilingual sentence-transformers) is the intended upgrade and has not been scored yet. LLM-generated answers have not been scored either.

## Configuration

All settings are environment variables prefixed `MANUAL_ASSISTANT_` (see `.env.example`). Point `LLM_BASE_URL`, `LLM_MODEL` and `LLM_API_KEY` at any OpenAI-compatible endpoint to use a hosted model instead of Ollama.
